## 経緯/ — その時どう判断したかの記録

**運用には要らない。**あとから「なぜこうなっているのか」を辿るためのもの。

| ファイル | 中身 |
|---|---|
| [経緯/報告_Cowork連携.md](経緯/報告_Cowork連携.md) | チャットがアプリと繋がっていなかったときの報告(2026-08-09) |
| [経緯/回答_献立の食い違い.md](経緯/回答_献立の食い違い.md) | 献立データの食い違いをどう解決するかの相談 |
| [経緯/点検で出た指摘.txt](経緯/点検で出た指摘.txt) | 多エージェント点検で出た指摘の一覧 |

古い前提のまま書かれているものが混ざっている。
**運用の判断は必ず [しくみ.md](しくみ.md) 側を正とすること。**
たとえば「Cowork がまだ繋がっていない」という記述は、
その後の調査で「クラウドからは原理的に繋がらない」と結論が変わっている。

## 使い方を直したいとき

`docs/` ではなく [../lib/help-content.ts](../lib/help-content.ts) を直す。
アプリの `/help` が読む唯一の出どころで、文書ファイルと二重に持つと必ず食い違う。
