## 0. 必ず読む — 方針.md

`C:\\Users\\mmizu\\jisui\\方針.md` に、この家の**お金の前提と決めごと**が書いてある。
お金の話(支出の分類・投資・カードの選び方・資産の相談)をする前に必ず開くこと。
DB には入っていないので、手元の記憶で答えると必ずずれる。

| 節 | 中身 | いつ使うか |
|---|---|---|
| 1. 固定事実 | 住宅ローンの条件、控除、現金、繰上返済の方針 | 資産や返済の相談 |
| 2. 投資方針書(IPS) | 何をどれだけ買うか | 投資の相談 |
| 3. 運用ルール | 積立と不定期投資の決まり | 同上 |
| **4. 家計・カード・銀行運用** | **どの支出をどのカードで払うか。銀行の役割分担** | **支出の記録・分類のたび** |

### 4章(カード・銀行)の要点

支出を記録するとき、その買い物が**方針どおりのカードで払われているか**を見る。
違っていたら黙って直さず、一言添える(「これは楽天カードのほうが還元が高いです」)。
還元のために店や買い方を変えることはしない、というのが本人の決めた原則。

- 共用の固定費(年100万まで)と、対象コンビニ・外食のタッチ決済 → 三井住友ゴールドNL
- 共用のその他すべて → 夫の楽天カード
- イオン系の20日・30日のみ → イオンカード
- 個人の支出 → 各自の楽天カード
- 三井住友は年100万到達後は使わない(タッチ7%対象店を除く)

**「年100万にあといくら残っているか」は聞かれたら答えられるようにする。**
三井住友ゴールドNL で払った当年ぶんの合計を transactions から出す。

## 1. 分類はまず辞書。AIの判断で上書きしない

店名から費目を決めるときは、必ず `expense_rules`(分類辞書・67件)を先に引く。

```python
category = j.classify("ライフ 西宮店")   # 部分一致で費目を返す。無ければ None
```

- **辞書に当たったら、その費目を機械的に使う。** AI が「これは日用品では」と思っても変えない
- **辞書に無い店は、必ず本人に確認する。** 推定費目を出して承認を得てから `j.add_rule()` で追記する
- 勝手に辞書へ登録しない

理由: 同じ店がその時々で違う費目になると、前月比が比較にならなくなる。

## 2. 重複は取り込まない

`dedup_hash = sha256(date|amount|merchant_raw)` で判定する。
`j.add_receipt()` は中で見ているので、そのまま使えば重複しない。

レシートで入れた分とカード明細が同じ買い物を指すことがある。
その可能性がある行は `needs_review=True` を立てる。アプリの家計画面に
「重複の確認が必要」として出る。

## 3. NISA積立・iDeCo は支出に数えない

資産の移動であって、消費ではない。月次の集計から除く。
`category` を「NISA積立」にしてある行がそれ。

## 4. 口座番号・カード番号は保存しない

CSV に含まれていたら、その列を捨ててから取り込む。
テーブルにも列を用意していない。

## 5. 金額や日付を推測で補完しない

読み取れない行はスキップして、何行スキップしたかを報告する。

## よく使う操作

```python
from db import Jisui
j = Jisui()

j.money("2026-08")        # 支出・収入・予算・資産・残高
j.investments()           # 保有銘柄・監視銘柄・直近の指標・資産の内訳
j.outlook()               # ローン残高の予定・俸給表
j.todos()                 # やること(未完了)
```

### レシートを記録する

```python
j.add_receipt(
    date="2026-08-09", amount=3070, merchant_raw="ライフ 西宮店",
    category=j.classify("ライフ 西宮店") or "食費",
    items=[{"item": "豚ロース", "price": 680}],
    inventory=[{"name": "豚ロース", "qty": 300, "unit": "g", "location": "冷蔵"}],
)
```

**1回で支出と在庫の両方に入る。** これが2つのアプリを1つにした一番の理由。

### 銘柄ウォッチを更新する

「ウォッチ銘柄を更新して」と言われたら、`watchlist` の各銘柄について
株価・PER・PBR・配当利回り・年間配当・年初来高値/安値を調べ、
`watch_history` に当日付で入れる。

```python
j.insert("watch_history", [{
    "code": "7203", "as_of": "2026-08-09", "price": 2790, "per": 10.2,
    "pbr": 1.1, "div_yield": 3.4, "dividend": 95,
    "note": "出典と時点を必ず書く",
}])
```

- **数値は必ず出典つきで記録し、推測で補完しない**
- **一般論としての「買い推奨」はしない。** 順位を付けるのは、
  `invest_policy` に入っている**この家の基準**に照らしたときの並びであって、
  誰にでも当てはまる助言ではない。理由と弱点を必ず添える。
  買うかどうかを決めるのはアプリで押すボタン(`stock_decisions`)のほう。

### 高配当の候補を出す

「高配当の候補を出して」と言われたら、**20銘柄前後を並べて、そのうち3つに
推薦の印を付ける**。まず基準を読む(勝手に決めない)。

```python
inv = j.investments()
inv["方針"]      # 1銘柄あたりの上限・4つの重み・足切り利回り
inv["判断"]      # 見送り済みの銘柄。理由も入っている
inv["保有銘柄"]  # すでに持っているもの(業種の偏りを見る)
```

見出しと候補を、**同じ `as_of`** で入れる。親子は日付で繋がっていて、
id では繋がっていない(片方だけ適用されても画面に出るようにするため)。

```python
day = "2026-09-02"
j.upsert("screenings", [{
    "as_of": day,
    "criteria": "東証プライム・予想利回り3.5%以上・直近5年で減配なし・単元30万円以下",
    "universe": "株探の予想利回りランキング上位80銘柄から",
    "note": "決算発表明けで数字が動いている銘柄がある",
}], on_conflict="household_id,as_of")

j.upsert("screening_candidates", [{
    "as_of": day, "code": "8058", "name": "三菱商事", "market": "東証P",
    "sector": "卸売", "price": 4776, "unit_shares": 100,
    "div_yield": 2.62, "dividend": 125, "per": 15.9, "pbr": 1.85,
    "payout_ratio": 41.6, "streak_years": 10, "progressive": True,
    "year_high": 6012, "year_low": 3610,
    "recommended": True, "rank": 1,
    "reason": "累進配当を中計で明文化。非資源の比率が上がって配当の振れが小さい",
    "risk": "資源価格と為替で利益が振れる。年初来では高値寄り",
    "source": "株探 2026-09-01 終値 / 会社の中期経営計画",
}], on_conflict="household_id,as_of,code")
```

- **点数は入れない。** 総合点はアプリが重みを使って計算する(`lib/screening.ts`)。
  こちらが入れるのは素の数字と、`recommended` / `rank` / `reason` / `risk` / `source`。
- **落ちた銘柄も入れる**(`recommended` を付けないだけ)。
  17銘柄が残っていないと「なぜこの3つだったか」が後から辿れない。
- **`risk` が書けない候補は入れない。** 弱点が見つからないのは、調べ足りていないだけ。
- **`payout_ratio` や `streak_years` が拾えなければ null のまま**にする。
  埋めると、アプリはそれを「分かっている数字」として点にしてしまう。
  ただし**4つの軸のうち半分も埋まらない候補は、一覧の下の組に落ちる**
  (利回りしか無い銘柄が、よく調べた銘柄より上に来ないようにしてある)。
  推薦するなら、利回り・増配・割安・配当性向を一通り埋めてから推すこと。
- すでに `stock_decisions` で「見送る」にした銘柄を、理由が変わっていないのに
  また推さない。出すなら「前回見送った理由がこう変わった」を `reason` に書く。
- 業種(`sector`)は必ず入れる。**銀行と商社だけの一覧にしない。**

### 保有銘柄を更新する

証券会社の残高CSVや画面を受け取ったら `holdings` に入れる(`as_of` はデータの日付)。
同じ日・同じ口座・同じ銘柄は入れ直しになる。

### 月次の振り返り

アプリの家計画面に費目別・推移・1食あたりコストが出るので、
ダッシュボードのHTMLを作る必要はなくなった(旧 `make_dashboard.py` は引退)。

チャット側でやる価値があるのは、数字を並べたうえでの**考察**のほう。
「先月より食費が1万円増えたのは、外食が4回増えたため」といった読み取りを書く。
